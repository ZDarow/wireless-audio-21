## 🔴 КРИТИЧНЫЕ (7 задач) — блокируют безопасность и работоспособность

### C1 — Двойная инициализация NVS
**Файл:** `firmware/master_s3_idf/main/main.cpp:363,372`  
**Проблема:** `nvs_flash_init()` вызывается в `app_main()` (стр. 363) и снова в `g_nvsConfig.init()` (стр. 372).  
**Патч:** Удалить вызов `nvs_flash_init()` из `app_main()` (строки 363-369), оставить только `g_nvsConfig.init()`.  
**Статус:** ⬜ Открыто

### C2 — CORS wildcard `*`
**Файл:** `firmware/master_s3_idf/components/web_server/src/web_server.cpp:456,462,491,497`  
**Проблема:** `Access-Control-Allow-Origin: *` на всех JSON/SSE ответах. Любой вредоносный сайт может делать кросс-доменные запросы.  
**Патч:** Убрать заголовок `Access-Control-Allow-Origin` из `sendJson()` и `sendText()`, или заменить на конкретный origin.  
**Статус:** ⬜ Открыто

### C3 — Отсутствие CSRF-защиты
**Файл:** `firmware/master_s3_idf/components/web_server/src/web_server.cpp:347` (и все onPost* обработчики)  
**Проблема:** Все state-changing POST endpoints (`/api/volume`, `/api/crossover`, `/api/system/reboot`, `/api/system/factory_reset`, `/api/system/ota`, `/api/wifi`) принимают запросы без CSRF-токена.  
**Патч:** Добавить в `WebServerCallbacks` коллбеки `getCsrfToken()` и `validateCsrfToken()`. В каждом `onPost*` проверять заголовок `X-CSRF-Token`.  
**Статус:** ⬜ Открыто

### C4 — OTA по HTTP без подписи прошивки
**Файл:** `firmware/master_s3_idf/components/ota_update/src/ota_update.cpp:23-36`  
**Проблема:** `esp_https_ota` принимает любой URL, нет проверки HTTPS, нет проверки подписи, нет `esp_ota_mark_app_valid_cancel_rollback()`.  
**Патч:** Разрешить только HTTPS URL (`strncmp(url, "https://", 8)`), добавить `esp_crt_bundle_attach`, добавить `esp_ota_mark_app_valid_cancel_rollback()` перед `esp_restart()`.  
**Статус:** ⬜ Открыто

### C5 — Жёстко заданный дефолтный пароль AP
**Файл:** `firmware/master_s3_idf/components/nvs_config/include/nvs_config.h:42`  
**Проблема:** `"1234567890"` зашит в коде. Уязвимость S-1.  
**Патч:** Убрать дефолтный пароль из кода (`char wifiApPassword[64] = {0}`), требовать настройки через Web UI при первом запуске.  
**Статус:** ⬜ Открыто

### C6 — UDP-аутентификация отключена по умолчанию
**Файл:** `firmware/master_s3_idf/main/main.cpp:447`  
**Проблема:** `g_cfg.udpAuthKey[0]` — пустая строка, `m_authEnabled = false`, принимаются все пакеты `0xA210` без проверки (уязвимость V4).  
**Патч:** Установить дефолтный случайный ключ в `NodeConfig` или требовать настройки через Web UI.  
**Статус:** ⬜ Открыто

### C7 — ESP-NOW peer накапливается без límites
**Файл:** `firmware/master_s3_idf/components/espnow_transport/src/espnow_transport.cpp:94`  
**Проблема:** `esp_now_add_peer()` вызывается при каждом `sendUnicast()`. Лимит ~20 пиров, нет удаления неактивных.  
**Патч:** Добавить метод `removePeer(const uint8_t* dstMac)`, отслеживать активность пиров, удалять неактивных при превышении лимита.  
**Статус:** ⬜ Открыто

## 🟠 ВЫСОКИЕ (8 задач) — надёжность и производительность

### H1 — I2S запись 1 семпла за вызов
**Файл:** `firmware/master_s3_idf/main/main.cpp:244`  
**Проблема:** `int16_t outBuf[1]` — запись 2 байт в DMA за вызов. При 48 кГц — 48 000 вызовов `i2s_channel_write()` в секунду, щелчки аудио, высокая нагрузка на CPU.  
**Патч:** Накопить батч из 64-128 семплов в локальный буфер, писать в I2S батчем.  
**Статус:** ⬜ Открыто

### H2 — Блокирующий UDP receive в 100 Гц цикле
**Файл:** `firmware/master_s3_idf/main/main.cpp:483`  
**Проблема:** `g_udpAudio.receive(10, ...)` может блокировать до 10 мс. Бюджет цикла 10 мс — может превыситься, вызывая пропуск тактов.  
**Патч:** Вынести приём UDP в отдельную FreeRTOS задачу с очередью, или сделать неблокирующим с таймаутом 1 мс.  
**Статус:** ⬜ Открыто

### H3 — WDT сброс после vTaskDelayUntil
**Файл:** `firmware/master_s3_idf/main/main.cpp:492-495`  
**Проблема:** `esp_task_wdt_reset()` вызывается после задержки. Если задержка задержится, WDT не сбросится вовремя.  
**Патч:** Поменять порядок: `esp_task_wdt_reset()` ДО `vTaskDelayUntil()`.  
**Статус:** ⬜ Открыто

### H4 — `esp_wifi_stop()` без проверки состояния
**Файл:** `firmware/master_s3_idf/main/main.cpp:298`  
**Проблема:** Если Wi-Fi не был запущен (ошибка инициализации), вызов `esp_wifi_stop()` может вернуть ошибку или привести к неопределённому поведению.  
**Патч:** Добавить проверку `g_wifi_inited` перед вызовом `esp_wifi_stop()`.  
**Статус:** ⬜ Открыто

### H5 — SSE блокирует HTTP задачу на 30 секунд
**Файл:** `firmware/master_s3_idf/components/web_server/src/web_server.cpp:462`  
**Проблема:** `vTaskDelay(pdMS_TO_TICKS(30000))` в `onSSE()` блокирует задачу HTTP сервера, не обрабатывая другие запросы.  
**Патч:** Реализовать полноценный SSE с отслеживанием активных клиентов и неблокирующей отправкой событий.  
**Статус:** ⬜ Открыто

### H6 — Частая запись в NVS изнашивает flash
**Файл:** `firmware/master_s3_idf/main/main.cpp:87-98,105-117`  
**Проблема:** `g_nvsConfig.save()` вызывается при каждом изменении громкости/кроссовера. NVS ~100k циклов записи, нет дебаунса.  
**Патч:** Добавить дебаунс (сохранять не чаще 1 раза в 5 секунд) или кэширование с отложенной записью.  
**Статус:** ⬜ Открыто

### H7 — Нет таймаута оффлайн сателлитов
**Файл:** `firmware/master_s3_idf/components/espnow_transport/src/espnow_transport.cpp:143-166`  
**Проблема:** `updateSatellite()` помечает сателлит онлайн навсегда. Нет проверки `lastSeenMs`.  
**Патч:** Добавить проверку `lastSeenMs` в главном цикле, помечать сателлит оффлайн если нет heartbeat > 5 секунд.  
**Статус:** ⬜ Открыто

### H8 — Относительный путь include
**Файл:** `firmware/master_s3_idf/main/main.cpp:24`  
**Проблема:** `#include "../components/i2s_output/include/i2s_output.h"` — ломается при изменении структуры файлов.  
**Патч:** Добавить `i2s_output` в `REQUIRES` в `main/CMakeLists.txt`, использовать `#include "i2s_output.h"`.  
**Статус:** ⬜ Открыто

## 🟡 СРЕДНИЕ (8 задач) — качество кода, поддерживаемость

### M1 — Неиспользуемая константа MDNS_MULTICAST_IP
**Файл:** `firmware/master_s3_idf/components/mdns_raw/src/mdns_raw.cpp:26`  
**Проблема:** Константа определена но не используется; код использует `PP_HTONL(LWIP_MAKEU32(...))`.  
**Патч:** Удалить константу или использовать её вместо дублирования логики.  
**Статус:** ⬜ Открыто

### M2 — Хрупкая перезапись rdlen в SRV ответе mDNS
**Файл:** `firmware/master_s3_idf/components/mdns_raw/src/mdns_raw.cpp:304-305`  
**Проблема:** `memcpy(buf + boff - 6, &srvRdlen, 2)` — перезапись уже записанных байт, легко сломать при изменении.  
**Патч:** Пересчитать размер буфера заранее, записать rdlen один раз перед данными.  
**Статус:** ⬜ Открыто

### M3 — `httpd_resp_send` без проверки возврата
**Файл:** `firmware/master_s3_idf/components/web_server/src/web_server.cpp:460`  
**Проблема:** Возвращает `ESP_OK` даже если отправка не удалась.  
**Патч:** Проверять возвращаемое значение `httpd_resp_send()`, логировать ошибки.  
**Статус:** ⬜ Открыто

### M4 — `strcpy` без проверки границ в NVS
**Файл:** `firmware/master_s3_idf/components/nvs_config/src/nvs_config.cpp:93,97`  
**Проблема:** Если значение в NVS длиннее буфера — переполнение stack.  
**Патч:** Заменить `strcpy` на `strncpy` с обнулением последнего байта.  
**Статус:** ⬜ Открыто

### M5 — Фиксированный стек-буфер 1208 байт в HMAC
**Файл:** `firmware/master_s3_idf/components/udp_audio/src/udp_audio.cpp:137`  
**Проблема:** Если payload > 1200 байт — переполнение stack. `m_rxBuffer` — 1500 байт, нет проверки `n <= sizeof(m_rxBuffer)`.  
**Патч:** Добавить проверку `n <= sizeof(m_rxBuffer)` перед копированием, использовать динамический буфер или ограничить размер.  
**Статус:** ⬜ Открыто

### M6 — Глобальные объекты в main.cpp
**Файл:** `firmware/master_s3_idf/main/main.cpp:51-67`  
**Проблема:** Все компоненты — глобальные переменные. Трудно тестировать, нет инверсии зависимостей.  
**Патч:** Инкапсулировать в класс `MasterApp` с конструктором, принимающим зависимости.  
**Статус:** ⬜ Открыто

### M7 — `strcasecmp` для имён DNS
**Файл:** `firmware/master_s3_idf/components/mdns_raw/src/mdns_raw.cpp:226`  
**Проблема:** Регистронезависимое сравнение имён DNS — DNS имена technically case-insensitive, но лучше точное сравнение для безопасности.  
**Патч:** Заменить `strcasecmp` на `strcmp` (DNS имена в нижнем регистре по стандарту).  
**Статус:** ⬜ Открыто

### M8 — DNS флаги не авторитетные
**Файл:** `firmware/master_s3_idf/components/dns_captive/src/dns_captive.cpp:49`  
**Проблема:** `AA=0` в ответе. Некоторые клиенты могут не принимать ответ как authoritative.  
**Патч:** Установить флаг AA=1 в ответах captive DNS.  
**Статус:** ⬜ Открыто
