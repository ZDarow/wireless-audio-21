# ТЗ: устранение проблем аудита

## P0 — критично

### 1. Утечка памяти в WebServer

**Где искать:** `firmware/common/web/web_server.h`, обработчики загрузки файлов в `firmware/master/common/web/`.

**Проблема:** `new File(...)` без парного `delete`/`reset` в обработчике загрузки.

**Действия:**
- найти все `new`/`malloc` в `firmware/common/web/` и `firmware/master/common/web/`;
- заменить на `std::unique_ptr`/RAII;
- добавить в `test/` host-тест: многократный вызов обработчика загрузки не увеличивает счётчик живых аллокаций (кастомный `operator new` со счётчиком).

**Приёмка:** `grep -rn "new " firmware/common/web/` — только умные указатели; тест проходит.

---

### 2. Пароли в NVS в открытом виде

**Где искать:** `firmware/common/config/storage.h`, `firmware/common/web/wifi_store.h`.

**Проблема:** Wi-Fi пароли пишутся через `putString` открыто.

**Действия:**
- инвентаризировать все секреты в NVS;
- создать `firmware/common/config/secure_storage.h`: шифрование секретов перед записью (переиспользовать существующую крипто-инфраструктуру проекта — ключи `AUDIO_ESPNOW_PMK/LMK`, PBKDF2);
- формат: `enc$<ver>$<iv_hex>$<data_hex>`;
- обратная совместимость: открытое значение при чтении мигрирует в зашифрованный формат и перезаписывается;
- тесты: туда-обратно, миграция старого формата, неверный ключ → ошибка без падения.

**Приёмка:** `grep -rn "putString" firmware/` — пароли не пишутся открыто; тесты проходят.

---

### 3. Блокирующие операции в аудио-цикле

**Где искать:** `firmware/master_s3/src/main.cpp`, `firmware/master/src/main.cpp`, `firmware/common/web/internet_check.h`.

**Проблема:** `WebServer.handleClient()` и сетевые проверки выполняются в одном цикле с аудио.

**Действия:**
- вынести сетевые задачи в отдельную FreeRTOS-задачу на ядро 0, приоритет ниже аудио-задачи;
- аудио-задача: приоритет >= 8, ядро 1, без блокирующих вызовов;
- `InternetMonitor` вызывается только из сетевой задачи;
- обмен между задачами — атомарные переменные или очереди, не разделяемые `String`.

**Приёмка:** в аудио-цикле нет вызовов веб-сервера и сетевых проверок; все 6 env собираются.

---

### 4. Отсутствие проверок nullptr в DSP-тракте

**Где искать:** `firmware/common/audio/` — `pcm_pipeline.h`, `delay_line.h`, `jitter_buffer.h`, `crossover.h`.

**Проблема:** обработка `nullptr`-буферов и нулевых размеров без проверки.

**Действия:**
- добавить проверки входных параметров во все публичные функции `firmware/common/audio/`;
- при невалидном входе — лог через существующий `logger.h` и безопасный возврат;
- тесты в `test/`: вызовы с `nullptr` и нулевым размером не падают.

**Приёмка:** тесты с `nullptr` проходят; `make test` зелёный.

---

### 5. Глобальные переменные сервисов

**Где искать:** `firmware/master_s3/src/main.cpp`, `firmware/master/src/main.cpp`.

**Проблема:** глобальные объекты сервисов (`AudioControlService`, `WifiManager`, `WebServerModule`, `InternetMonitor`).

**Действия:**
- создать `firmware/common/app_context.h` — агрегатор сервисов;
- передавать контекст в `setup()` явно, зависимости через конструктор/`init()`;
- рефакторить по одному сервису за коммит;
- поведение консоли и REST API не меняется.

**Приёмка:** в `main.cpp` нет прямых глобальных объектов сервисов; все 6 env собираются; существующие тесты проходят.

## P1 — важно

### 6. Интеграционные тесты

**Где:** `test/` (создать `test/integration/`).

**Действия:**
- тест пайплайна: источник-заглушка → громкость → кроссовер → задержка → приёмник-заглушка; проверить частотное разделение (саб — низкие, сателлиты — высокие);
- тест пакета туда-обратно: сериализация/десериализация `audio_packet` с джиттером и задержкой;
- тест конфига: `config.env` → генерация → значения в `node_config.h`.

**Приёмка:** `make test` в `test/` проходит; тесты проверяют поведение системы, а не отдельные функции.

**Где:** `test/` (создать `test/concurrency/`).

**Проблема:** нет тестов на одновременный доступ к общим данным.

**Действия:**

- проверка отсутствия гонок через атомарные счётчики нарушений.

**Приёмка:** тесты проходят без детектированных нарушений.

### 8. Тест производительности (базовый)

**Где:** `test/` (создать `test/perf/`).

**Действия:**
- измерить время обработки фиксированного буфера (512 сэмплов, стерео, полный тракт: громкость + кроссовер + задержка);
- зафиксировать порог (например, < 1 мс на хосте);
- при незначительном превышении — предупреждение, не ошибка.

**Приёмка:** тест запускается через `make test` и печатает измеренное время.

### 9. Оптимизация I2S-вывода

**Где искать:** `firmware/common/audio/i2s_output.h`/`.cpp`.

**Проблема:** возможная поэмпловая запись вместо пакетной.

**Действия:**
- проверить реализацию: если запись по сэмплу — перевести на буферную запись целым блоком;
- убедиться, что конфигурация I2S использует `dma_buf_count`/`dma_buf_len` адекватного размера и `use_apll = true`;
- учесть: плата без PSRAM (N8R2) — буферы должны влезать во внутренний heap;
- модульный тест с mock `i2s_write`: запись вызывается блоками, не по сэмплу.

**Приёмка:** запись буфером; сборки всех env успешны; тест проходит.

### 10. Магические числа и константы

**Где искать:** `firmware/common/transport/espnow.cpp`, `firmware/common/web/auth.cpp`, другие места с литеральными порогами.

**Проблема:** неименованные числовые пороги (250, -90, 100 и т.п.).

**Действия:**
- вынести все магические числа в именованные константы с пояснением происхождения в комментариях;
- группировать по смыслу в `namespace` (например, `EspNowLimits`, `AuthLimits`).

**Приёмка:** `grep -rn "== [0-9]" firmware/` и аналоги не показывают неименованных порогов в логике.
