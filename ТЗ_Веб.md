# Техническое задание  
## Веб-интерфейс мастер-узла беспроводной аудиосистемы 2.1 на ESP32-S3

---

## 1. Назначение веб-интерфейса

Веб-интерфейс предназначен для настройки, управления и диагностики мастер-узла аудиосистемы 2.1 на базе ESP32-S3.

Основное назначение:

- настройка подключения мастера к Wi-Fi сети с доступом в интернет;
- управление аудиопараметрами системы 2.1;
- настройка задержек каналов;
- настройка кроссовера;
- управление громкостью;
- мониторинг состояния мастера и сателлитов;
- проверка доступа к сети интернет;
- обновление прошивки;
- просмотр диагностики и логов.

---

## 2. Обязательные требования

### 2.1 Доступ мастера к интернету

Мастер-узел должен уметь подключаться к Wi-Fi сети с выходом в интернет.

Основной режим работы:

```text
ESP32-S3 Master → Wi-Fi STA → домашний роутер → Internet
```

Мастер должен:

- подключаться к сохранённой Wi-Fi сети;
- автоматически переподключаться после сбоя питания;
- проверять наличие доступа в интернет;
- отображать статус интернета в веб-интерфейсе;
- использовать интернет для NTP, OTA и диагностики.

### 2.2 Настройка Wi-Fi через веб-интерфейс

Веб-интерфейс обязан содержать раздел настройки Wi-Fi.

Раздел должен позволять:

- сканировать доступные сети;
- выбирать сеть из списка;
- вводить пароль;
- подключаться к сети;
- сохранять сеть;
- удалять сохранённые сети;
- просматривать текущий IP-адрес;
- просматривать статус интернета.

### 2.3 Локальный доступ

Веб-интерфейс должен быть доступен внутри локальной сети:

```text
http://audio-master.local
http://<IP_ADDRESS>
```

Удалённый доступ через интернет по умолчанию не реализуется.

## 3. Режимы работы сети

### 3.1 Основной режим: STA + Internet

Мастер подключён к домашней Wi-Fi сети.

```text
Smartphone / PC / Tablet
        │
        │ LAN / Wi-Fi
        ▼
ESP32-S3 Master
        │
        ▼
Internet
```

В этом режиме доступны:

- веб-интерфейс;
- REST API;
- приём аудио от смартфона;
- управление сателлитами;
- NTP;
- OTA.

### 3.2 Режим настройки: AP + Captive Portal

Если сохранённые Wi-Fi сети отсутствуют или мастер не может подключиться к интернету в течение заданного времени, мастер переходит в режим настройки.

```text
SSID: Audio21-Setup
IP:   192.168.4.1
```

Пользователь подключается к этой сети со смартфона или ПК и открывает:

```text
http://192.168.4.1
```

Мастер должен поддерживать captive portal:

```text
/generate_204
/hotspot-detect.html
/fwlink
```

Эти адреса должны перенаправлять на страницу настройки Wi-Fi.

### 3.3 Поведение после сохранения Wi-Fi

После сохранения корректных данных мастер должен:

1. Сохранить конфигурацию в NVS или LittleFS.
2. Попытаться подключиться к указанной сети.
3. Получить IP-адрес по DHCP или по статической настройке.
4. Выполнить проверку интернета.
5. Перейти в основной режим при успешном подключении.
6. Вернуться в AP-режим при неудаче.

## 6. Страница Wi-Fi

### 6.1 Обязательность

Это обязательная страница веб-интерфейса.

### 6.2 Функции

Страница должна обеспечивать:

- сканирование сетей;
- вывод списка сетей;
- отображение SSID;
- отображение уровня сигнала;
- отображение типа защиты;
- отображение канала;
- ручной ввод скрытой сети;
- ввод пароля;
- подключение;
- сохранение сети;
- проверку подключения;
- проверку интернета.

### 6.3 Поля формы Wi-Fi

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| SSID | text / select | Да | Имя сети |
| Password | password | Для защищённых сетей | Пароль WPA/WPA2/WPA3 |
| Hidden network | checkbox | Нет | Для скрытых сетей |
| IP mode | select | Нет | DHCP / Static |
| IP address | text | Для Static | Локальный IP |
| Netmask | text | Для Static | Маска сети |
| Gateway | text | Для Static | Шлюз |
| DNS | text | Для Static | DNS-сервер |
| Auto reconnect | checkbox | Нет | Автоматическое переподключение |

### 6.4 Результат подключения

После попытки подключения интерфейс должен показать:

```text
Connecting...
IP received: 192.168.1.55
Internet check: OK
```

или ошибку:

```text
Wi-Fi connection failed
Wrong password
No IP received
No internet access
```

### 6.5 Список сохранённых сетей

Интерфейс должен отображать сохранённые профили:

```text

Last connection status
Priority

```

Минимальное количество профилей:


## 7. Страница Internet

### 7.1 Назначение

```text

```

### 7.3 Статусы интернета

| Статус | Описание |
|---|---|
| `disabled` | проверка выключена |
| `checking` | выполняется проверка |
| `online` | интернет доступен |
| `offline` | интернет недоступен |
| `captive_portal` | обнаружен портал авторизации |
| `dns_error` | ошибка DNS |
| `no_route` | нет маршрута |

### 7.4 Проверка интернета

Мастер должен выполнять проверку доступности интернета.

Метод проверки:

```text
HTTP GET или HTTP HEAD до лёгкого endpoint
```

Рекомендуемый endpoint по умолчанию:

```text
http://connectivitycheck.gstatic.com/generate_204
```

Альтернативные endpoint:

```text
http://detectportal.firefox.com/success.txt
http://captive.apple.com/hotspot-detect.html
```

Пользователь должен иметь возможность изменить URL проверки.

### 7.5 Настройки интернета

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| Internet check enabled | true | Включить проверку |
| Check interval | 30 s | Интервал проверки |
| Check timeout | 5 s | Таймаут проверки |
| Check URL | gstatic generate_204 | URL проверки |
| NTP enabled | true | Синхронизация времени |
| NTP server | pool.ntp.org | Сервер времени |
| Timezone | UTC | Часовой пояс |

|---|---:|---:|

### 9.4 Дополнительные режимы



## 13. Страница Logs

### 13.1 Назначение

Просмотр системных и сетевых событий.

### 13.2 Категории логов

```text
BOOT
WIFI
INTERNET
AUDIO
TRANSPORT
SATELLITE
CONFIG
ERROR
```

### 13.3 Формат записи

```text
[timestamp] [level] [module] message
```

Пример:

```text
[2026-08-11 18:22:14] [INFO] [WIFI] Connected to MyNetwork
[2026-08-11 18:22:15] [INFO] [NET] IP: 192.168.1.55
[2026-08-11 18:22:16] [INFO] [NET] Internet check OK
```

### 13.4 Ограничения

Логи не должны:

- хранить пароли;
- хранить полный ответ HTTP-запросов;
- занимать всю файловую систему;
- снижать качество аудиопотока.

Рекомендуемый размер кольцевого буфера логов:

```text
16–64 KB
```

## 19. Требования к пользовательскому интерфейсу

### 19.1 Адаптивность

Интерфейс должен корректно работать на:

```text
смартфоне;
планшете;
десктопе;
узком экране 360 px;
широком экране 1920 px.
```

### 19.2 Основной язык

По умолчанию:

```text
Русский
```

Опционально:

```text
Английский
```

### 19.3 Производительность

Требования:

```text
загрузка главной страницы < 2 секунд в локальной сети;
ответ API < 300 ms при нормальной Wi-Fi связи;
интерфейс не должен блокироваться при опросе статуса;
использовать polling или WebSocket не чаще 1 раза в секунду.
```

### 19.4 Обновление состояния

Рекомендуется:

```text
GET /api/status каждые 2 секунды
или WebSocket /ws
```

### 19.5 Внешние ресурсы

Запрещается обязательная загрузка внешних CDN-библиотек.

Все файлы интерфейса должны храниться локально:

```text
LittleFS
gzip
```

Допускается использовать интернет только для:

```text
OTA;
NTP;
проверки соединения;
опциональной проверки обновлений.
```

## 21. Логика подключения к интернету

### 21.1 Состояния

```text
WIFI_IDLE
WIFI_SCANNING
WIFI_CONNECTING
WIFI_CONNECTED
WIFI_FAILED
IP_WAITING
IP_RECEIVED
INTERNET_CHECKING
INTERNET_ONLINE
INTERNET_OFFLINE
AP_FALLBACK
```

### 21.2 Алгоритм при старте

```text
1. Загрузить сохранённые Wi-Fi профили.
2. Выбрать профиль с наивысшим приоритетом.
3. Выполнить сканирование сетей.
4. Подключиться к найденной сохранённой сети.
5. Если сеть не найдена, перейти в AP fallback.
6. После подключения запросить IP.
7. Выполнить проверку интернета.
8. Если интернет доступен, перейти в рабочий режим.
9. Если интернет недоступен, повторить проверку.
10. После N неудач включить AP fallback.
```

### 21.3 Таймауты

| Параметр | Значение |
|---|---:|
| Wi-Fi connect timeout | 15 s |
| DHCP timeout | 10 s |
| Internet check timeout | 5 s |
| Internet retry interval | 10 s |
| AP fallback after failures | 3 failures |
| Reboot watchdog | опционально |

## 23. Безопасность

### 23.1 Обязательные требования

```text
доступ к настройкам только после входа;
пароль администратора;
session timeout;
запрет изменения Wi-Fi без авторизации;
CSRF token для POST/PUT/DELETE;
rate limit для login и Wi-Fi scan;
валидация всех входных данных.
```

### 23.2 Ограничение доступа

По умолчанию веб-сервер должен обслуживать только локальную сеть.

Рекомендуется блокировать:

```text
доступ из внешних сетей;
прямые запросы с неизвестных подсетей;
неавторизованный доступ к API.
```

### 23.3 HTTPS

HTTPS является опциональным, но желательным.

Если HTTPS реализуется:

```text
использовать самоподписанный сертификат;
разрешить пользователю загрузить собственный сертификат;
не требовать обязательного HTTPS в локальной сети, если это destabilзирует Wi-Fi audio.
```

## 25. Поведение при ошибках

### 25.1 Нет Wi-Fi сети

Показать:

```text
Saved network not found.
Please select another network or enable AP setup mode.
```

Действие:

```text
перейти в AP fallback.
```

### 25.2 Неверный пароль

Показать:

```text
Wi-Fi connection failed.
Check password and try again.
```

Действие:

```text
разрешить повторный ввод.
```

### 25.3 Нет интернета

Показать:

```text
Wi-Fi connected, but no internet access.
```

Возможные действия:

```text
повторить проверку;
изменить DNS;
изменить internet check URL;
переподключиться.
```

### 25.4 Captive portal

Показать:

```text
Network requires login.
Open captive portal page or use another network.
```

## 28. Критерии приёмки

Веб-интерфейс считается готовым, если выполнены следующие условия.

### 28.1 Wi-Fi

```text
можно просканировать сети;
можно выбрать сеть;
можно ввести пароль;
мастер подключается к сети;
мастер получает IP;
настройки сохраняются после перезагрузки;
неверный пароль не приводит к зависанию;
при отсутствии сети доступен AP fallback.
```

### 28.2 Интернет

```text
мастер показывает статус интернета;
мастер реально имеет доступ в интернет;
NTP синхронизирует время;
проверка интернета выполняется по расписанию;
статус отображается на Dashboard.
```

### 28.3 Аудио

```text
громкость изменяется;
mute работает;
кроссовер изменяется;
задержки изменяются;
настройки сохраняются.
```

### 28.4 Система

```text
доступ к веб-интерфейсу защищён паролем;
можно перезагрузить устройство;
можно посмотреть логи;
можно обновить прошивку;
можно скачать диагностику.
```

### 28.5 Стабильность

```text
веб-интерфейс не прерывает аудиопоток;
Wi-Fi настройки не сбрасываются;
мастер автоматически восстанавливает подключение;
нет утечек памяти при длительной работе;
web API отвечает при активном воспроизведении.
```

## 30. Итоговое обязательное поведение мастера

Мастер должен работать следующим образом:

```text
1. При первом включении создать Wi-Fi сеть Audio21-Setup.

3. Позволить выбрать домашнюю Wi-Fi сеть.
4. Позволить ввести пароль Wi-Fi.
5. Подключиться к домашней сети.
6. Получить IP-адрес.
7. Проверить доступ к интернету.
8. Показать статус интернета.
9. Разрешить управление аудиосистемой.
10. Автоматически восстанавливать подключение после перезагрузки.
```
