# Руководство для контрибьюторов — Wireless Audio 2.1

Спасибо за интерес к проекту! Это руководство поможет вам внести свой вклад.

## Поведенческий кодекс
Ожидается, что все контрибьюторы будут соблюдать уважительный и профессиональный тон в общении.

## Как внести вклад

### 1. Сообщение об ошибке или предложение функции
Создайте issue, используя соответствующий шаблон в `.github/ISSUE_TEMPLATE/`.

### 2. Pull Request
1. Сделайте fork репозитория.
2. Создайте ветку с описательным именем (например, `feature/esp-now-encryption` или `fix/udp-auth-key`).
3. Внесите изменения.
4. Запустите хост-тесты: `make -C test test` — все должны быть зелёными.
5. Зафиксируйте изменения в соответствии со стилем коммитов (см. ниже).
6. Откройте Pull Request в ветку `main`.

## Стиль коммитов (Conventional Commits)

Используйте формат: `<тип>: <описание>`

Типы:
- `feat:` — новая функция
- `fix:` — исправление бага
- `docs:` — изменения в документации
- `style:` — форматирование, отсутствие точек с запятой и т.д. (без изменений кода)
- `refactor:` — рефакторинг кода (без исправления багов или добавления функций)
- `perf:` — улучшение производительности
- `test:` — добавление или исправление тестов
- `ci:` — изменения в CI/CD конфигурации
- `security:` — исправления уязвимостей безопасности

Примеры:
```
feat: добавить SSE endpoint /api/events
fix: заменить String на char[] в веб-путях
docs: добавить CHANGELOG.md
ci: добавить dependabot.yml
security: V4 — UDP-аутентификация источника (HMAC-SHA256)
```

Язык коммитов: русский, повелительное наклонение.

## Требования к коду

- C++17, header-only модули без зависимостей от Arduino-железа (для host-тестов).
- Все изменения в `firmware/common` должны проходить хост-тесты (`make -C test test`).
- Нет `String` в веб-коде (используйте `char[]`/`const char*` для предотвращения фрагментации heap).
- Все новые документы в `docs/` добавляются только через PR с ревью.

## Тестирование

- Хост-тесты (без железа): `make -C test test`
- Сборка прошивки (PlatformIO): `pio run -c platformio.master.ini` (мастер), `pio run -e satellite_s3_left/right` (сателлиты)
- Железо-зависимое покрывается только ручной проверкой.

## Безопасность

Если вы нашли уязвимость, пожалуйста, не открывайте публичный issue. Напишите на адрес безопасности, указанный в `SECURITY.md`.
